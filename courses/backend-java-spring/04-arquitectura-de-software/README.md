# 04. Arquitectura de software

Este módulo refuerza la teoría de arquitectura con decisiones aplicadas a un backend Java y Spring.

1. [Fundamentos de arquitectura](01-fundamentos.md): arquitectura frente a diseño, atributos de calidad y tradeoffs.
2. [Estilos arquitectónicos](02-estilos-arquitectonicos.md): monolito, monolito modular, microservicios y un ADR para la API de cursos.
3. [Arquitectura en capas con Spring](03-arquitectura-en-capas-con-spring.md): responsabilidades, dependencias y límites de la transacción.
4. [Arquitectura limpia y hexagonal](04-arquitectura-limpia-y-hexagonal.md): regla de dependencias, puertos y adaptadores para el último cupo.
5. [Diseño orientado al dominio (DDD)](05-diseno-orientado-al-dominio.md): lenguaje compartido, contextos delimitados e invariantes de inscripción.
6. [Microservicios](06-microservicios.md): despliegue independiente, propiedad de datos y extracción del catálogo.
7. [Comunicación entre servicios](07-comunicacion-entre-servicios.md): llamadas síncronas, eventos e idempotencia.
8. [Resiliencia](08-resiliencia.md): tiempos de espera, reintentos, aislamiento y degradación controlada.
9. [Escalabilidad y rendimiento](09-escalabilidad-y-rendimiento.md): métricas, pruebas de carga y diagnóstico de cuellos de botella.
10. [Arquitectura de datos](10-arquitectura-de-datos.md): propiedad, integridad, transacciones y evolución del esquema.
11. [Seguridad](11-seguridad.md): identidad, autorización y protección del flujo de inscripción.
12. [Observabilidad](12-observabilidad.md): métricas, logs y trazas para diagnosticar la API de cursos.
13. [Documentación de arquitectura](13-documentacion-de-arquitectura.md): vistas C4, ADR y evidencia verificable.

**Ejemplo resuelto:** [ADR 001: monolito modular para la API de cursos](adr/001-monolito-modular.md).

**Evidencia:** una propuesta para una API de cursos que explique qué se prioriza, qué se sacrifica y cómo se verificará la decisión.
